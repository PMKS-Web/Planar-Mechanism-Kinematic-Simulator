# Tokens

A token is a CSS custom property defined on `:root`: a color, a radius, a shadow or a gap with a
name. Components refer to it with `var(--name)` rather than writing the value again.

The table below is **not a hand-kept list.** When this page opens, it walks every stylesheet the
gallery loaded, and lists each custom property declared on `:root`. Those stylesheets are the app's
global styles, taken from its own build target. For each property the table shows:

- where it was declared;
- the value as written;
- the value in effect;
- a sample, when the value is a color, a shadow, a radius or a length.

Because of that, the table shows what is really defined, with nothing to update. The app's tokens
live in [`src/styles/_tokens.scss`](../../styles/_tokens.scss), grouped by role: surfaces, borders,
text tiers, brand, selection, accent, warning, refusal, success, canvas marks, shadows, radii and the
card gap. Add one there and it appears here the next time the gallery loads.

A numbered token such as `--text-disabled-3` is a near-duplicate, kept only so the move to tokens
changed no pixels. It is a merge waiting to happen, not a shade to reach for.

Angular Material's theme also writes dozens of its own `--mat-*` tokens onto the same element. They
are listed separately, collapsed, at the bottom of the table.

Every stylesheet arrives in one bundle, so a token's file cannot show whose it is. The rule it was
declared in can:
- A rule that declares only `--mat-*` properties was generated by Material.
- Any other rule was written in this app. For example, `--mat-warning-color` is written beside
  `--border-radius` in `src/styles/_tokens.scss`, so it counts as an app token.

**New colors must be tokens.** A raw hex value in a component stylesheet is a color nobody can
find, rename or check for contrast. `npm run lint:styles` (stylelint) fails CI on one anywhere but
the token file.
